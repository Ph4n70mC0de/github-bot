# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |

## Reporting a Vulnerability

If you discover a security vulnerability in this repository, please report it responsibly:

1. **Do not** open a public GitHub issue for security vulnerabilities.
2. Email the maintainers at [arjscandes73@gmail.com] with:
   - A description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if any)

## Security Controls

This project implements the following controls:

- **Webhook signature verification**: All incoming GitHub webhooks are verified via `x-hub-signature-256`. See `src/server/webhook-server.ts`.
- **Least privilege**: Only required GitHub App permissions are requested. See `Plan.md` �4.
- **Secrets management**: Secrets are loaded from environment variables. Never commit `.env` or private keys.
- **Rate limit handling**: GitHub API rate limits are respected with retry/backoff. See `src/utils/rate-limiter.ts`.
- **Idempotency**: Handlers are designed to be safe under webhook retries.
- **Bot-loop prevention**: Handlers guard against events generated by the bot itself.

## Dependencies

- Dependencies are pinned via `package-lock.json`
- Run `npm audit` regularly and apply patches
- Report supply-chain issues to maintainers

## Deployment

- Store secrets in your platform's secret manager (AWS Secrets Manager, GCP Secret Manager, Railway/Render env vars, etc.)
- Do not bake secrets into Docker images
- Use HTTPS for webhook endpoints
- Rotate webhook secrets and app private keys periodically
